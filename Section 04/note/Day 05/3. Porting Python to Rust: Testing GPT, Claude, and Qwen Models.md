# ১. Porting Python → Rust মানে কী?

এটা শুধু “syntax change” না—এটা হলো:

* Dynamic → Static typing conversion
* Garbage collected → Ownership-based memory model
* High-level logic → System-level implementation

---

## Example

### Python

```python id="p1"
def add_list(nums):
    return sum(nums)
```

---

### Rust

```rust id="r1"
fn add_list(nums: &[i32]) -> i32 {
    nums.iter().sum()
}
```

👉 এখানে AI-কে বুঝতে হয়:

* type inference (`i32`)
* borrowing (`&[i32]`)
* iterator idiom

# ৪. Real Benchmark Example

## Python Input

```python id="p2"
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)
```

---

## GPT Output

```rust id="g1"
fn factorial(n: u64) -> u64 {
    match n {
        0 => 1,
        _ => n * factorial(n - 1),
    }
}
```

✔ idiomatic match usage
✔ correct type inference

---

## Claude Output

```rust id="c1"
fn factorial(n: u64) -> u64 {
    if n == 0 {
        1
    } else {
        n * factorial(n - 1)
    }
}
```

✔ simplest and clean
✔ very readable

---

## Qwen Output

```rust id="q1"
fn factorial(n: i32) -> i32 {
    if n == 0 {
        return 1;
    }
    return n * factorial(n - 1);
}
```

✔ correct logic
⚠ less idiomatic Rust
⚠ unsafe type choice (`i32`)

# ৭. Common AI Mistakes in Python → Rust

## ❌ 1. Wrong Borrowing

```rust
fn f(s: String) -> String
```

👉 inefficient move

---

## ❌ 2. Wrong Type Mapping

Python:

```python
list[int]
```

Bad Rust:

```rust
Vec<int>
```

Correct:

```rust
Vec<i32>
```

---

## ❌ 3. Overuse of cloning

```rust
s.clone()
```

AI models often overuse clone → performance drop
