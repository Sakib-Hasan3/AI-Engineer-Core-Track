## Topic: Connecting to Multiple Frontier Models with APIs

**Examples: OpenAI, Claude, Gemini**

### 1. Basic Idea

API মানে হলো **Application Programming Interface**।

সহজভাবে:

**তোমার app বা code সরাসরি AI model-এর সাথে কথা বলে API-এর মাধ্যমে।**

যেমন তুমি ChatGPT website-এ গিয়ে prompt লিখো।
কিন্তু API ব্যবহার করলে তোমার নিজের Python app, web app, chatbot, agent, automation system—সবকিছু model-এর কাছে request পাঠাতে পারে।

```text
Your App / Agent
      ↓
API Request
      ↓
OpenAI / Claude / Gemini Model
      ↓
API Response
      ↓
Your App shows or uses the answer
```

OpenAI-এর current API docs-এ Responses API-কে text/image input, text output, stateful interaction, built-in tools, function calling ইত্যাদির জন্য ব্যবহার করা হয়। ([OpenAI Developers][1]) Claude API হলো RESTful API, যা `api.anthropic.com` endpoint দিয়ে Claude models এবং managed agents-এ programmatic access দেয়। ([Claude Platform][2]) Gemini API content generation, text, image, audio, code, tools, function calling, JSON mode ইত্যাদি support করে। ([Google AI for Developers][3])

## 2. Frontier Model কী?

**Frontier model** হলো সবচেয়ে advanced AI model family, যেগুলো reasoning, coding, text generation, image understanding, tool use, planning, agentic workflow ইত্যাদিতে strong।

Examples:

| Company   | Model Family  |
| --------- | ------------- |
| OpenAI    | GPT models    |
| Anthropic | Claude models |
| Google    | Gemini models |

Agentic AI শেখার সময় এগুলো গুরুত্বপূর্ণ, কারণ agent নিজে model না।
Agent সাধারণত model + tools + memory + planning + execution logic দিয়ে তৈরি হয়।

```text
Agent = LLM + Tools + Memory + Planning + Actions
```

## 3. কেন Multiple Models connect করতে হয়?

একটা serious AI system শুধু এক provider-এর উপর depend করলে risk থাকে।

কারণ:

1. **Cost difference**
   একেক model-এর price আলাদা।

2. **Quality difference**
   কোনো model coding-এ ভালো, কোনো model writing-এ ভালো, কোনো model long-context analysis-এ ভালো।

3. **Speed difference**
   fast response দরকার হলে cheaper/faster model use করা যায়।

4. **Fallback দরকার**
   OpenAI API fail করলে Claude বা Gemini use করা যেতে পারে।

5. **Task-based routing**
   User যদি coding question করে → OpenAI/Claude
   User যদি long PDF বা multimodal task করে → Gemini/Claude/OpenAI
   User যদি cheap summary চায় → smaller model

## 4. Main Architecture

```text
User
 ↓
Your App / Agent
 ↓
Model Router
 ├── OpenAI API
 ├── Claude API
 └── Gemini API
 ↓
Normalize Response
 ↓
Final Answer
```

### Model Router কী?

**Model Router** হলো logic যা decide করে কোন task কোন model-এ যাবে।

Example:

```text
If task = coding → Claude or OpenAI
If task = image + text → Gemini or OpenAI
If task = cheap summary → smaller model
If main model fails → fallback model
```

## 5. API Call-এর Basic Structure

প্রায় সব AI API call-এ কিছু common জিনিস থাকে:

```text
1. API Key
2. Model name
3. Prompt / Messages
4. Parameters
5. Response handling
```

### 1. API Key

API key হলো password-এর মতো secret token।

এটা দিয়ে provider বুঝে:

```text
কে request করছে?
কোন account থেকে bill হবে?
কত request করা হচ্ছে?
```

Important:

```text
API key কখনো GitHub-এ push করা যাবে না।
.env file-এ রাখতে হবে।
```

Example:

```env
OPENAI_API_KEY=your_key_here
ANTHROPIC_API_KEY=your_key_here
GEMINI_API_KEY=your_key_here
```

## 6. Prompt বনাম Messages

Simple prompt:

```text
"Explain API in simple words"
```

But chat models usually message format use করে:

```json
[
  {"role": "system", "content": "You are a helpful tutor."},
  {"role": "user", "content": "Explain APIs in Bangla."}
]
```

### Role-এর কাজ

| Role      | Meaning                               |
| --------- | ------------------------------------- |
| system    | Model-এর behavior/instruction set করে |
| user      | User-এর question                      |
| assistant | Model-এর previous answer              |
| tool      | External tool result                  |

Agentic AI-তে message history খুব গুরুত্বপূর্ণ, কারণ agent previous step দেখে next step নেয়।

Basic idea:

```text
Your code → OpenAI Responses API → GPT model → response
```

Use cases:

```text

Coding assistant
Agentic workflow
Tool calling
Structured JSON output

Web search
Reasoning task
```

OpenAI docs বলছে latest models Responses API এবং SDKs দিয়ে ব্যবহার করা যায়। ([OpenAI Developers][4])

## 10. Same Task, Different API

ধরো user বলেছে:

```text
Summarize this article in 5 bullet points.
```

তোমার app তিনভাবে call করতে পারে:

```text
OpenAI call:
model = GPT model
input = article + instruction

Claude call:
model = Claude model
messages = article + instruction

Gemini call:
model = Gemini model
contents = article + instruction
```

Problem হলো:
প্রতিটা company-এর request format আলাদা।

Solution:

```text
Common wrapper বানাতে হয়।
```

## 11. Common Wrapper কী?

Common wrapper হলো নিজের বানানো function/class যা সব provider-এর API call এক format-এ আনে।

Example concept:

```python
def call_model(provider, prompt):
    if provider == "openai":
        return call_openai(prompt)

    elif provider == "claude":
        return call_claude(prompt)

    elif provider == "gemini":
        return call_gemini(prompt)
```

আরও advanced version:

```python
def ask_ai(task_type, prompt):
    if task_type == "coding":
        provider = "claude"

    elif task_type == "multimodal":
        provider = "gemini"

    else:
        provider = "openai"

    return call_model(provider, prompt)
```

## 12. Normalization কেন দরকার?

OpenAI, Claude, Gemini—সব API response format একরকম না।

একটা response হয়তো এমন:

```json
{
  "output_text": "Answer here"
}
```

আরেকটা এমন:

```json
{
  "content": [
    {"text": "Answer here"}
  ]
}
```

আরেকটা এমন:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [{"text": "Answer here"}]
      }
    }
  ]
}
```

তাই app-এর ভিতরে final format same করা ভালো:

```json
{
  "provider": "openai",
  "model": "model-name",
  "answer": "Final answer here",
  "usage": {
    "input_tokens": 100,
    "output_tokens": 200
  }
}
```

এটাই **response normalization**।

## 13. Important Parameters

### temperature

Controls creativity.

```text
temperature low = more focused, less random
temperature high = more creative, more random
```

Use:

```text
Exam answer → low temperature
Creative story → high temperature
Coding → low/medium temperature
Brainstorming → medium/high temperature
```

---

### max_tokens / max_output_tokens

Model কত বড় answer দিবে সেটা control করে।

```text
Small value → short answer
Large value → long answer
```

---

### system instruction

Model-এর behavior set করে।

Example:

```text
You are a Bangla tutor. Explain everything simply with examples.
```

---

### streaming

Streaming মানে response একবারে না এসে ধীরে ধীরে আসবে।

```text
Without streaming:
Wait → full answer

With streaming:
word by word / chunk by chunk answer
```

Chatbot UI-তে streaming useful, কারণ user দ্রুত response দেখতে পায়।

Gemini API docs অনুযায়ী streamGenerateContent SSE দিয়ে response chunks পাঠাতে পারে। ([Google AI for Developers][7])

## 14. Function Calling / Tool Calling

Agentic AI-তে এটা সবচেয়ে important part।

Normal LLM শুধু text generate করে।
কিন্তু function calling দিলে model decide করতে পারে:

```text
আমি কি calculator call করব?
আমি কি database search করব?
আমি কি weather API call করব?
আমি কি email পাঠাব?
```

Flow:

```text
User asks: "What is the weather today?"
        ↓
Model understands it needs weather tool
        ↓
App calls weather API
        ↓
Weather result goes back to model
        ↓
Model gives final answer
```

Diagram:

```text
User
 ↓
LLM
 ↓ decides
Tool Call Needed?
 ↓ yes
External Tool / API
 ↓
Tool Result
 ↓
LLM
 ↓
Final Answer
```

OpenAI Responses API function calling এবং external systems/data access support করে। ([OpenAI Developers][1]) Gemini API custom function calling এবং built-in tools support করে। ([Google AI for Developers][8])

## 15. Rate Limit

Rate limit মানে তুমি নির্দিষ্ট সময়ের মধ্যে কত request করতে পারবে।

Gemini docs অনুযায়ী rate limits সাধারণত RPM, TPM, RPD দিয়ে measure হয়:

```text
RPM = Requests per minute
TPM = Tokens per minute
RPD = Requests per day
```

একটা limit exceed করলে rate limit error আসে। ([Google AI for Developers][9])

Common error:

```text
429 Too Many Requests
```

Solution:

```text
Retry after delay
Exponential backoff
Queue system
Fallback model
Request batching
```

## 16. Error Handling

API use করলে error আসবেই।

Common errors:

| Error   | Meaning               | Solution                 |
| ------- | --------------------- | ------------------------ |
| 401     | Wrong API key         | Key check                |
| 429     | Rate limit exceeded   | Retry/backoff            |
| 400     | Bad request format    | JSON/body check          |
| 500     | Provider server issue | Retry/fallback           |
| Timeout | Response আসতে দেরি    | Timeout increase / retry |

Agentic AI project-এ fallback খুব useful:

```text
Try OpenAI
 ↓ fail
Try Claude
 ↓ fail
Try Gemini
 ↓ fail
Return safe error message
```

## 17. Best Practice for Multi-Model Agent

### Recommended structure

```text
project/
│
├── main.py
├── .env
├── model_router.py
├── providers/
│   ├── openai_provider.py
│   ├── claude_provider.py
│   └── gemini_provider.py
├── tools/
│   ├── search_tool.py
│   └── calculator_tool.py
└── utils/
    └── response_normalizer.py
```

### Why this structure is good?

```text
OpenAI code আলাদা
Claude code আলাদা
Gemini code আলাদা
Routing logic আলাদা
Tool logic আলাদা
Main app clean থাকে
```

## 19. Real Agentic AI Example
